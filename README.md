В репозитории представлены решения двух практических задач платформы **Яндекс CodeRun**. Для каждой задачи приведено подробное объяснение хода решения, обоснование выбора структур данных и анализ вычислительной сложности.

# Задача 1. Среднее из трёх чисел (три способа решения)
### 1. Ссылка на задачу

* **Платформа: Яндекс CodeRun**

* **Задача:** «Упорядочить три числа и вывести среднее» (https://coderun.yandex.ru/problem/median-out-of-three)

### 2. Исходный код решения на Python (PEP-8)
```python

def method_1_sort(a, b, c):
    # Способ 1 - сортировка через nums
    nums = [a, b, c]
    nums.sort()
    return nums[1]


def method_2_loop(a, b, c):
    # Способ 2 - через цикл
    nums = [a, b, c]
    for i in range(3):
        x = nums[i]
        y = nums[(i + 1) % 3]
        z = nums[(i + 2) % 3]
        if (y <= x <= z) or (z <= x <= y):
            return x


def method_3_conditions(a, b, c):
    # Способ 3 - через сравнение
    if (a <= b <= c) or (c <= b <= a):
        return b
    elif (b <= a <= c) or (c <= a <= b):
        return a
    else:
        return c


def main():
    a, b, c = map(int, input().split())

    # ВЫБОР СПОСОБА
    # выберите для way 1, 2 или 3
way = 2

if way == 1:
        result = method_1_sort(a, b, c)
    elif way == 2:
        result = method_2_loop(a, b, c)
    elif way == 3:
        result = method_3_conditions(a, b, c)
    else:
        print("Неверный номер способа")
        return

print(result)


if __name__ == "__main__":
    main()
```

### 3. Пояснение: подробное описание хода решения

Все три способа решают одну и ту же задачу: найти число, которое после упорядочивания по возрастанию окажется на втором месте.

* **Способ 1 — сортировка списка:**
    Складываем три числа в список [a, b, c] и вызываем sort(). После сортировки по возрастанию nums[0] — минимум, nums[1] — среднее, nums[2] — максимум. Ответ — nums[1]. Это самый короткий и наглядный вариант.

* **Способ 2 — цикл с проверкой условия «между двумя другими»:**
    На каждой итерации выбираем одно число x из тройки, а два других обозначаем y и z. Используем круговой обход через (i + 1) % 3 и (i + 2) % 3, чтобы для i = 0 получить (1, 2), для i = 1 — (2, 0), для i = 2 — (0, 1). Условие (y <= x <= z) or (z <= x <= y) означает, что x лежит между y и z (в любом порядке). Как только такое число найдено — возвращаем его. Этот способ показывает, как обойтись без готовой сортировки.

* **Способ 3 — вложенные условия без цикла:**
    Перебираем три возможных случая: «среднее — это b», «среднее — это a», «среднее — это c». Условие a <= b <= c проверяет, что b между a и c по возрастанию, а c <= b <= a — по убыванию. Вместе они покрывают все ситуации, когда b — среднее. Если ни один вариант не подошёл, значит среднее — c.

* **Переключатель way:**
    Все три способа оформлены как функции с одинаковым интерфейсом f(a, b, c) -> int. В main() переменная way определяет, какую функцию вызвать. Это позволяет легко продемонстрировать любой из способов, не меняя остальной код.

### 4. Обоснование выбора алгоритма и структур данных

* **Почему три способа?**
    Я решил показать три способа, так как только один не имеет никакой ценности и слишком лёгок для отдельного задания. Задача имеет несколько естественных решений, и их сравнение показывает разные подходы к одной проблеме: готовые библиотечные функции (sort), итеративный перебор с условием (цикл) и чисто логический разбор случаев (вложенные if).

* **Почему список?**
    Список в Python — самая лёгкая структура для хранения трёх чисел с произвольным доступом по индексу за O(1). Для способа 1 нужен именно изменяемый список, чтобы вызвать sort(). Для способа 2 нужен доступ по кругу через индексы — список подходит идеально.

* **Почему не множество или словарь?**
    set удаляет повторяющиеся значения. Если a = b = c, множество схлопнется в один элемент, и мы потеряем информацию.
    dict здесь избыточен: нет пар «ключ — значение», нет необходимости в хешировании.

* **Почему функции с одинаковым интерфейсом?**
    Единая сигнатура f(a, b, c) -> int — это принцип «программирование на интерфейсе». Снаружи неважно, как именно функция ищет ответ; можно заменить реализацию, не трогая точку вызова.

### 5. Анализ сложности

* **Временная сложность (Time Complexity): O(1)**
Для всех трёх способов количество операций фиксировано и не зависит от значений чисел:

  Способ 1: sort() для трёх элементов — константное число сравнений (не более 3).

  Способ 2: цикл ровно на 3 итерации.

  Способ 3: не более 2 проверок условий.

* **Пространственная сложность (Space Complexity): O(1)**

  Способ 1: список nums из трёх элементов.

  Способ 2: список nums и три локальные переменные.

  Способ 3: только входные параметры a, b, c.
Объём памяти не зависит от размера входных данных.

## Задача 462. Диагональная мозаика (площадь фигур)
### 1. Ссылка на задачу

* **Платформа: Яндекс CodeRun**
* **Задача: «Мозаика с диагональными контурами»** (https://coderun.yandex.ru/problem/black-and-white?compiler=swift)
* **Тип: поиск площади фигур, ограниченных диагоналями в клетчатой сетке.**

2. Исходный код решения на Python (PEP-8)
```python

import sys
from collections import deque


def solve():
    input = sys.stdin.readline
    n, m = map(int, input().split())
    grid = [input().strip() for _ in range(n)]

    # Направления: 0 = верх, 1 = право, 2 = низ, 3 = лево
    di = [-1, 0, 1, 0]
    dj = [0, 1, 0, -1]

    # side_part[i][j][s] — id части, которая касается стороны s клетки (i, j)
    side_part = [[[-1] * 4 for _ in range(m)] for _ in range(n)]
    part_area2 = []      # площадь части, умноженная на 2
    part_count = 0

    for i in range(n):
        for j in range(m):
            ch = grid[i][j]

            if ch == '.':
                p = part_count
                part_count += 1
                part_area2.append(2)  # целая клетка
                for s in range(4):
                    side_part[i][j][s] = p

            elif ch == '/':
                p1 = part_count
                part_count += 1
                part_area2.append(1)  # треугольник
                p2 = part_count
                part_count += 1
                part_area2.append(1)

                # p1: верх и лево
                side_part[i][j][0] = p1
                side_part[i][j][3] = p1
                # p2: право и низ
                side_part[i][j][1] = p2
                side_part[i][j][2] = p2

            elif ch == '\\':
                p1 = part_count
                part_count += 1
                part_area2.append(1)
                p2 = part_count
                part_count += 1
                part_area2.append(1)

                # p1: верх и право
                side_part[i][j][0] = p1
                side_part[i][j][1] = p1
                # p2: низ и лево
                side_part[i][j][2] = p2
                side_part[i][j][3] = p2

    outside = part_count
    adj = [[] for _ in range(part_count + 1)]

    for i in range(n):
        for j in range(m):
            for s in range(4):
                p = side_part[i][j][s]
                ni = i + di[s]
                nj = j + dj[s]

                if 0 <= ni < n and 0 <= nj < m:
                    # Внутренние рёбра добавляем один раз: сверху и справа
                    if s == 0 or s == 1:
                        s_opp = (s + 2) % 4
                        q = side_part[ni][nj][s_opp]
                        adj[p].append(q)
                        adj[q].append(p)
                else:
                    # Граница картинки — соединение с внешней областью
                    adj[p].append(outside)
                    adj[outside].append(p)

    # BFS от внешней области
    visited = [False] * (part_count + 1)
    visited[outside] = True
    queue = deque([outside])

    while queue:
        v = queue.popleft()
        for u in adj[v]:
            if not visited[u]:
                visited[u] = True
                queue.append(u)

    total_area2 = 0
    for i in range(part_count):
        if not visited[i]:
            total_area2 += part_area2[i]

    print(total_area2 // 2)


if __name__ == "__main__":
    solve()

```

### 3. Пояснение: подробное описание хода решения

Контуры фигур нарисованы диагоналями внутри клеток. Каждая диагональ делит клетку на два треугольника. Нужно найти суммарную площадь всех фигур — то есть всех областей, замкнутых внутри контуров.

**Разбиение клеток на части:**

Каждый символ сетки трактуется так:

. — целая клетка (площадь 1);

 / — диагональ из левого-нижнего угла в правый-верхний; клетка делится на два треугольника (площадь каждого 0.5);

 \ — диагональ из левого-верхнего угла в правый-нижний; тоже два треугольника.

Чтобы избежать дробей, площадь каждой части умножаем на 2:

целая клетка → 2;

треугольник → 1.

**Нумерация частей и сторон:**
 Для каждой части запоминаем, каких сторон клетки она касается. Это ключ к соединению частей между соседними клетками:

/: один треугольник касается верха и лева, другой — права и низа;

\: один треугольник касается верха и права, другой — низа и лева;

.: единственная часть касается всех четырёх сторон.
        Массив side_part[i][j][s] хранит id части, касающейся стороны s клетки (i, j).

**Построение графа смежности:**
Две части из соседних клеток соединяются ребром, если они касаются общей стороны клеток. Например, часть, касающаяся правой стороны клетки (i, j), соединяется с частью, касающейся левой стороны клетки (i, j + 1). Если сторона выходит за пределы сетки, часть соединяется с фиктивным узлом outside — «внешней областью».

**Поиск внешней области через BFS:**
Запускаем поиск в ширину от узла outside. Все части, до которых BFS добрался, находятся снаружи фигур. Те, что остались непосещёнными, лежат внутри замкнутых контуров.

**Подсчёт площади:**
Суммируем part_area2 для всех внутренних частей. Так как мы хранили удвоенную площадь, в конце делим на 2. По условию площадь фигур целая, поэтому деление происходит нацело.

### 4. Обоснование выбора алгоритма и структур данных

* Почему граф смежности частей? 
    Контуры делят плоскость на области, и задача сводится к поиску областей, не соединённых с внешней границей. Это классическая задача о заливке (flood fill), которая естественно формулируется на графе: вершины — части клеток, рёбра — общие стороны. Такой подход корректен для любых замкнутых контуров и не требует отдельного выделения циклов диагоналей.

* Почему BFS, а не DFS
    Оба варианта дают одинаковую сложность O(V + E). BFS выбран из-за итеративной реализации на deque — он не упирается в лимит рекурсии при больших сетках и читается линейно.

* Почему массив side_part?
    Он позволяет за O(1) определить, какая часть касается нужной стороны клетки. Альтернатива — каждый раз пересчитывать по символу — усложнила бы код и добавила ветвлений.

    Почему умножение площади на 2?
    Это избавляет от вещественных чисел и проблем с округлением. Все площади хранятся как целые, а итог делится на 2 один раз в конце.

    Почему фиктивный узел outside?
Он упрощает обработку границы: не нужно отдельно рассматривать внешние стороны клеток и писать для них особую логику. Все «выходы за пределы» ведут в один узел.

   Почему не формула Гаусса (shoelace)?
   Для этого пришлось бы явно выделять каждый замкнутый цикл диагоналей, следить за ориентацией и суммировать площади треугольников. При произвольных контурах это заметно сложнее в реализации и легче ошибиться. Метод заливки через граф частей — надёжнее и проще для понимания.

### 5. Анализ сложности

   Временная сложность (Time Complexity): O(n × m)

   Построение частей и заполнение side_part — один проход по всем клеткам: O(n × m).

   Построение рёбер — один проход по всем клеткам и четырём сторонам: O(n × m).

   BFS: число вершин не превышает 2 × n × m + 1, число рёбер — O(n × m). BFS работает за O(V + E) = O(n × m).

   Подсчёт площади — один проход по всем частям: O(n × m).
   Итого — линейное время относительно числа клеток.

    Пространственная сложность (Space Complexity): O(n × m)
    Хранятся:

   сетка grid размера n × m;

   массив side_part размера n × m × 4;

   список part_area2 длины не более 2 × n × m;

   граф смежности adj с числом вершин не более 2 × n × m + 1 и числом рёбер O(n × m);

   массивы visited и очередь BFS.
   Всё укладывается в O(n × m). При ограничениях n, m ≤ 100 это максимум порядка 4 × 10⁴ ячеек в side_part и около 2 × 10⁴ вершин графа — несколько мегабайт памяти, что более чем достаточно.
